# 循迹 Trace · 团队版部署手册（Linux）

本手册对应 `Trace-team-linux-*.tar.gz` 部署包。包内自带 Python 运行时、全部依赖、
MariaDB 与前端页面，**目标机不需要安装 Python / MySQL，也不需要联网**。

---

## 1. 部署结构

```
/opt/trace/                 程序目录（升级时整体替换）
├── install.sh              安装 / 升级（幂等，不改数据）
├── run.sh                  启动（先拉起内置 MariaDB，再起 Web 服务）
├── stop.sh                 停止（Web + 本次启动的 MariaDB）
├── scripts/
│   ├── db.sh               MariaDB 启停与路径解析
│   └── backup.sh           一致性备份
├── runtime/                Python 3.12 + 依赖 + MariaDB（构建时固定版本）
├── game_agent/             后端代码
├── web/dist/               前端页面
├── .env                    本机配置（密钥 / 数据目录 / 数据库连接串）
└── 部署手册.md

~/.trace-team/              数据目录（默认，可用 --data-dir 改）
├── mysql/                  MariaDB datadir（全部业务数据）
├── mysql_port              数据库端口
├── mysql_password          数据库账号 trace 的密码
├── chat_uploads/           聊天附图
├── uploads/                头像 / 壁纸
├── projects/               各项目工作区（代码仓库）
├── logs/                   mariadb.err / run.out
└── backups/                backup.sh 的默认输出目录
```

**程序与数据分离**：升级只替换程序目录，数据目录一个字节都不动。

数据库模型：一个「团队」下有多「项目」，账号按项目分派；模型档位、智能体（提示词与模型绑定）、
项目记忆、MCP、消息通道都支持按项目配置，未单独配置时回落到团队默认。

## 2. 目标机要求

| 项 | 要求 |
| --- | --- |
| CPU / 系统 | x86_64 Linux，glibc >= 2.17（Ubuntu / Debian / CentOS / RHEL / Rocky / Alma / Fedora / openSUSE） |
| 不支持 | Alpine（musl）、ARM、32 位 |
| 内存 | 建议 >= 2GB（多人并发对话按需增加） |
| 磁盘 | 建议 >= 5GB（程序约 400MB，其余为数据库、项目工作区与备份） |
| 账号 | 普通账号运行；不要用 root（数据目录会归 root） |
| 可选命令 | `git`、`svn`：只有项目启用 Git/SVN 同步时才需要。系统已装就直接用；没装可用一键安装版或离线包补（见 3.1） |
| 端口 | Web 18888/TCP；MariaDB 仅监听 127.0.0.1，无需对外开放 |

部署前检查：

```bash
uname -m                       # 必须是 x86_64
ldd --version | head -1        # glibc >= 2.17
df -h /opt ~                   # 磁盘余量
getenforce 2>/dev/null || true # RHEL 系看 SELinux 状态
```

## 3. 安装

```bash
sudo mkdir -p /opt/trace
sudo tar -xzf Trace-team-linux-*.tar.gz -C /opt/trace
sudo chown -R "$USER":"$USER" /opt/trace
cd /opt/trace

bash install.sh                          # 数据目录默认 ~/.trace-team
# 或指定数据盘与数据库端口：
bash install.sh --data-dir /data/trace --db-port 33307
```

`install.sh` 会：

1. 创建数据目录（mysql / chat_uploads / uploads / projects / logs / tmp）；
2. 首次安装初始化内置 MariaDB；**已存在 `mysql/` 时只补程序、不动数据**；
3. 生成 `.env`（数据目录 / 主密钥 / 数据库连接串），已有 `.env` 只同步连接串，
   主密钥为空时自动补一个；
4. 幂等建库建账号，并在升级时执行 `mariadb-upgrade`；
5. 一键安装版还会检查 git/svn：系统有就跳过，缺的用包内离线包补（见 3.1）。

安装完成后可直接启动。

### 3.1 Git / SVN：系统优先，缺的自动补

只有项目要在「团队 → 项目配置」里绑定 Git/SVN 仓库、对话前自动同步时才需要 git / svn。
这两种情况都支持：

**A. 服务器自己装（普通包 `Trace-team-linux-*.tar.gz`）**

系统里已有 `git` / `svn` 就直接用，Trace 不做任何干预。
没有就按发行版自己装，或随时补一个离线包：

```bash
apt install git subversion      # Debian / Ubuntu
dnf install git subversion      # RHEL / CentOS / Rocky / Alma / Fedora
```

```bash
# 不联网、不用 root 的离线补装包（git 2.45.2 + subversion 1.14.3 + 依赖库）
tar xzf Trace-team-vcs-linux-x86_64.tar.gz
cd Trace-team-vcs
bash install.sh                 # 自动找 /opt/trace；也可 bash install.sh /path/to/trace
```

**B. 一键安装版（文件名带 `-with-vcs`）**

包里已内置上面的离线 git/svn，`install.sh` 会自动扫描：

- 系统已有 git / svn → 跳过，不重复装；
- 缺哪个就只补哪个，装到 `<Trace目录>/vendor/vcs`；
- 两个都有 → 什么都不做；
- 不想让它碰 git/svn：`bash install.sh --no-vcs`。

**运行时的优先级：系统优先，包内补位**

`run.sh` 启动时按这个规则拼 PATH：

1. `PATH` 里能找到的 `git` / `svn`（系统装的、管理员自己装的）优先生效；
2. 系统没有的，才用 `vendor/vcs/bin` 里的包内版本；
3. 想强制用包内版本（比如系统 git 太旧）：

```bash
# 在解压后的 Trace-team-vcs 目录里跑（会装齐两个并写优先标记）：
bash install.sh --prefer-bundled /opt/trace
# 或直接 touch /opt/trace/vendor/vcs/prefer-bundled
# 改回系统优先：rm /opt/trace/vendor/vcs/prefer-bundled，重启 Trace
```

其他说明：

- 全程离线、不需要 root、不需要系统包管理器；x86_64 + glibc >= 2.17 即可；
- 实际用到包内 git 时会自动指定包内 CA 证书（`vendor/vcs/ssl/cacert.pem`），系统 git 不受影响；
- 补装时会做本地 `git init/commit/clone` 和 `svnadmin + file:// checkout` 自检，失败会明确报出来；
- 卸载：删掉 `<Trace目录>/vendor/vcs` 即可，不动数据库和项目；
- 升级 Trace 主包不会删除 `vendor/vcs`。

> 用 root 安装时，数据目录也归 root；之后必须用同一账号启动，否则会因权限失败。

## 4. 启动与停止

```bash
cd /opt/trace
bash run.sh                # 前台（Ctrl+C 停）
bash run.sh --daemon       # 后台，日志 <数据目录>/logs/run.out
bash stop.sh               # 停止 Web 与内置 MariaDB
```

- 默认监听 `0.0.0.0:18888`（`.env` 的 `GA_HOST` / `GA_PORT`）。
- 端口被占用时自动顺延，实际地址见启动输出或日志。
- 同一数据目录只允许一个实例；重复启动会被单实例守卫拦下并提示已在运行的地址。

### 用 systemd 托管（推荐生产环境）

`/etc/systemd/system/trace.service`：

```ini
[Unit]
Description=Trace Team
After=network.target

[Service]
Type=forking
User=trace
Group=trace
WorkingDirectory=/opt/trace
ExecStart=/usr/bin/bash /opt/trace/run.sh --daemon
ExecStop=/usr/bin/bash /opt/trace/stop.sh
PIDFile=/opt/trace/.run.pid
TimeoutStartSec=180
TimeoutStopSec=60

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now trace
sudo systemctl status trace
journalctl -u trace -f
```

> `run.sh` 会先启动 MariaDB 再起服务；`stop.sh` 会把两者都收掉，因此 systemd 的
> ExecStart/ExecStop 直接用它即可，不要另外写 MariaDB 单元。

## 5. 首次登录与初始化

浏览器打开 `http://<服务器IP>:18888/`：

1. 管理员 `admin` / `666666` 登录，**强制修改密码**后才能进入；
2. 「设置 → 模型配置」：添加模型供应商（OpenAI 兼容 / Anthropic），拉取或手填模型目录
   （可逐个设置上下文窗口与视觉能力）。供应商与密钥是团队级共用；
3. 「团队 → 新建项目」：可在此绑定该项目默认使用的对话模型、并发限制、Git/SVN、消息通道；
4. 「团队 → 新建账号」：开发 / 需求角色，分派到项目；
5. 「设置 → 智能体」：顶部「作用范围」不选项目 = 团队默认（提示词 + 模型）；
   选某个项目 = 只覆盖该项目的提示词/模型，未覆盖的字段自动继承团队默认
   （解析顺序：项目专属 → 团队默认 → 出厂）；
6. 「设置 → 项目记忆 / MCP 服务器」：开关在页面内选项目，均按项目隔离，
   成员只能看到自己项目的条目；
7. 成员登录后只看到被分派项目的会话与用量，模型由管理员按项目绑定，成员不能自行切换。
   **需求角色是后端硬只读**：对话强制 `analyze`，工具表里没有写文件/执行命令/起服务/派发子agent，
   只能读代码、检索内容、做汇报；开发角色才可改文件、跑命令并提交代码。

## 6. 升级（数据不丢）

严格按顺序（先停服务，避免旧进程继续写库）：

```bash
cd /opt/trace
bash scripts/backup.sh          # 强烈建议：升级前备份
bash stop.sh
tar -xzf Trace-team-linux-新版本.tar.gz -C /opt/trace   # 覆盖程序文件
bash install.sh
bash run.sh --daemon
```

升级时 `install.sh` 保证：

- 检测到 `<数据目录>/mysql` 就**跳过初始化**，只补程序与依赖；
- 保留 `.env`、`chat_uploads`、`uploads`、`projects`、`logs`；
- `mariadb-upgrade` 幂等；程序启动时的迁移只做「建表 / 加列」，
  不删表、不删列、不改已有数据。

换目录安装：

```bash
mkdir -p /opt/trace-new && tar -xzf 新包.tar.gz -C /opt/trace-new
cd /opt/trace-new && bash install.sh --data-dir /旧数据目录
```

只要 `.env` 的 `GA_DATA_DIR` 指向旧数据目录，就会沿用全部数据。

## 7. 备份与恢复

### 7.1 备份（不用停服务）

```bash
cd /opt/trace
bash scripts/backup.sh                      # 默认输出到 <数据目录>/backups
bash scripts/backup.sh --out /mnt/backup    # 备份到另一块盘 / NAS 挂载点
bash scripts/backup.sh --no-projects        # 项目工作区很大时跳过
```

产物：

| 文件 | 内容 |
| --- | --- |
| `db-<时间>.sql.gz` | 数据库事务一致性快照（InnoDB `--single-transaction`） |
| `files-<时间>.tar.gz` | chat_uploads / uploads / mysql_port / mysql_password |
| `env-<时间>.bak` | `.env`（含 `GA_SECRET_KEY`，恢复登录态必需） |
| `projects-<时间>.tar.gz` | 项目工作区（默认包含） |

建议用 cron + 异地同步：

```cron
30 3 * * * cd /opt/trace && bash scripts/backup.sh --out /mnt/backup >/dev/null 2>&1
```

### 7.2 恢复（新机器或回滚）

```bash
# 1) 解压程序包（同版本或更新版本）
sudo mkdir -p /opt/trace && sudo tar -xzf Trace-team-linux-*.tar.gz -C /opt/trace
sudo chown -R "$USER":"$USER" /opt/trace && cd /opt/trace

# 2) 还原 .env（没有它 install 会生成一套新密钥与新数据目录）
cp /备份/env-<时间>.bak .env && chmod 600 .env

# 3) 还原数据目录（路径与 .env 中 GA_DATA_DIR 一致）
mkdir -p ~/.trace-team
tar -xzf /备份/files-<时间>.tar.gz -C ~/.trace-team
tar -xzf /备份/projects-<时间>.tar.gz -C ~/.trace-team

# 4) 只启动数据库，导入 SQL 快照
bash -c 'cd /opt/trace && source scripts/db.sh && db_start'
export MYSQL_PWD="$(cat ~/.trace-team/mysql_password)"
zcat /备份/db-<时间>.sql.gz | runtime/mariadb/bin/mariadb \
  --defaults-file="$HOME/.trace-team/mysql/my.cnf" -u trace
unset MYSQL_PWD

# 5) 启动服务
bash run.sh --daemon
```

如果 `~/.trace-team/mysql` 不存在（全新机器），先运行一次 `bash install.sh`
初始化空库，再执行第 4 步导入。

### 7.3 迁移到另一台机器

按 7.2 做即可。`GA_SECRET_KEY` 一致时已登录用户无需重新登录；
不一致只影响登录态，不影响账号、项目与历史数据。

## 8. 网络、安全与反向代理

- `.env` 默认 `GA_HOST=0.0.0.0`，供内网同事访问；只允许本机时改 `127.0.0.1`。
- 防火墙放行 Web 端口：

  ```bash
  # firewalld
  sudo firewall-cmd --permanent --add-port=18888/tcp && sudo firewall-cmd --reload
  # ufw
  sudo ufw allow 18888/tcp
  ```

- 只在内网使用，**不要直接暴露公网**。需要 HTTPS 时，用 Nginx / Caddy 反代
  `http://127.0.0.1:18888`，并把 `GA_HOST` 改回 `127.0.0.1`。
- 内置 MariaDB 只监听 `127.0.0.1`，不需要对局域网开放。
- `admin` 初始密码 `666666` 只能用于首次登录，系统强制改密；不要与其他系统复用密码。

## 9. SELinux（RHEL / CentOS / Rocky / Alma）

SELinux 开启时，`/opt` 下的自编译 MariaDB 可能被拒绝执行或写数据目录。先确认：

```bash
sudo ausearch -m avc -ts recent | tail -20
```

临时验证（仅排查用）：

```bash
sudo setenforce 0
```

确认为 SELinux 后，任选一种长期方案：

1. 给程序目录打 `bin_t` / 给数据目录打可写标签：

   ```bash
   sudo semanage fcontext -a -t bin_t "/opt/trace/runtime(/.*)?"
   sudo semanage fcontext -a -t container_file_t "/home/<用户>/.trace-team(/.*)?"
   sudo restorecon -Rv /opt/trace "$HOME/.trace-team"
   ```

2. 或按公司规范为整套服务配置专用 SELinux 策略；
3. 若公司允许，把服务部署在关闭 SELinux 的专用内网机器上。

## 10. 常见问题

| 现象 | 排查 |
| --- | --- |
| MariaDB 起不来 | 看 `<数据目录>/logs/mariadb.err`；常见为数据目录权限、磁盘满、33306 端口被占 |
| 启动报「运行时依赖不完整」 | 包解压不完整，重新完整解压后重跑 `install.sh` |
| 页面打不开 | 确认 `GA_HOST`、防火墙 18888、进程是否在跑（`logs/run.out`） |
| 端口总是变 | 18888 被占用后会自动顺延；释放端口或改 `GA_PORT` 后重启 |
| 升级后登录全部失效 | `.env` 的 `GA_SECRET_KEY` 变了；恢复旧 `.env` 即可，数据不受影响 |
| 升级后功能异常 | 确认先 `stop.sh` 再覆盖程序；查看 `logs/run.out` 的迁移日志 |
| 忘记管理员密码 | 其他管理员在「团队」页重置；唯一管理员用：`runtime/python/bin/python3 -m game_agent.cli reset-password admin`（重置为 666666，强制改密） |
| 想改数据目录 | 优先用界面「设置 → 存储空间 → 迁移」：自动停内置 MariaDB → 整体复制 → 改写 `.env` → 重启后清理旧目录。若提示「被环境变量 GA_DATA_DIR 固定」，先去掉启动脚本/systemd 里的 `GA_DATA_DIR`（`.env` 里的不算锁死，会被自动改写）；也可以按老办法手工搬：停服务 → 拷贝数据目录 → 改 `.env`（保留 `GA_SECRET_KEY`）→ 启动 |
| Git/SVN 同步失败 | 先 `which git svn` 看是否装上（没装见 3.1），再看凭证/远端地址；手工 `git clone` 验证网络 |

## 12. 自己打包（维护者）

在 **x86_64 Linux 构建机**（有 node/npm、curl、tar、binutils）执行：

```bash
bash packaging/linux-team/build-package.sh
# 产物：dist/Trace-team-linux-<版本>-<时间>.tar.gz 与 .sha256（普通包，不含 git/svn）
```

依赖 wheel 固定按 **manylinux2014（glibc 2.17）** 档位安装，并在打包末尾做符号版本审计：
任何二进制要求 `GLIBC` > 2.17、`GLIBCXX` > 3.4.19 或 `CXXABI` > 1.3.7 都会让构建失败，
避免在较新构建机（如 Ubuntu 24.04）上打出的包在 CentOS 7 / 麒麟 / 欧拉等老机器上
`ImportError: CXXABI_x.y not found`。审计结果写在包内 `runtime/VERSIONS.txt`。

要出「一键安装版」（内置离线 git/svn，安装时扫描系统、缺哪个补哪个）：

```bash
bash packaging/linux-team/build-vcs-bundle.sh    # 先做离线 git/svn 包（需 conda，可复用缓存）
bash packaging/linux-team/build-package.sh --with-vcs
# 额外产物：dist/Trace-team-linux-<版本>-<时间>-with-vcs.tar.gz
```

`--vcs-bundle PATH` 可指定已有的离线包；用 `--no-fetch --with-vcs` 可以完全离线重打。
单独分发的离线补装包由 `build-vcs-bundle.sh` 产出：`dist/Trace-team-vcs-linux-x86_64.tar.gz`。

常用参数：

| 参数 | 作用 |
| --- | --- |
| `--no-build` | 不重建前端，直接用现有 `web/dist` |
| `--no-fetch` | 不联网，只用 `packaging/linux-team/vendor/` 里的运行时与 MariaDB |
| `--with-vcs` | 额外产出一键安装版（内置离线 git/svn） |
| `--vcs-bundle PATH` | 指定离线 git/svn 包（默认 `dist/Trace-team-vcs-linux-x86_64.tar.gz`） |
| `--python-runtime PATH` | 指定本机 Python 运行时目录或 install_only 包 |
| `--mariadb PATH` | 指定本机 MariaDB 目录或 bintar 包 |
| `--out DIR` | 输出目录（默认 `./dist`） |

构建脚本会把 `docs/部署手册.md`、`scripts/backup.sh` 一并打进包。
升级固定版本时改构建脚本顶部的 `PY_VER_TAG` / `MARIA_VER`。
